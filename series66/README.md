# シリーズ66：オートマトン ─ p5.js コード集

状態と遷移だけでできた「計算する機械」― **オートマトン**を自分で描いて、動かして、確かめるワークショップ（110分）のコード集です。自動販売機と信号機の状態機械から始めて、DFA の設計、NFA と部分集合構成、DFA の最小化、正規表現から NFA へ（トンプソン構成）、積の構成と言語の演算、ポンピング補題ゲーム、字句解析器、スタックつきのプッシュダウンオートマトン、文脈自由文法と CYK 構文解析、チューリング機械、忙しいビーバーと停止問題、ゲームの敵キャラの状態機械、エイホ-コラシック法、そして音とカメラまで、どれも**ライブラリを使わずに本当に計算した**シミュレーションです。
[p5.js Web Editor](https://editor.p5js.org/) にコピー＆ペーストするだけで動きます。

## 🌐 コード集サイト

**https://r-shibusawa.github.io/p5-interactive-art/series66/**

## 使い方（p5.js Web Editor）

1. https://editor.p5js.org/ を開く
2. `sketch.js` の中身を全部消して（`Ctrl/⌘ + A` → `Delete`）、コードを貼り付ける
3. 左上の ▶（実行）ボタンを押す
4. どのスケッチも一番下に「オートマトンの道具」（DFA・NFA・部分集合構成・最小化・積の構成、正規表現の構文解析とトンプソン構成、状態遷移図の描画と編集、チューリング機械、自己テストなど）があるので、**一番下まで全部コピー**する。実行したらまずキャンバスを1回クリック（キー操作が届くように）。🔊 音を使うスケッチ（14）は**音量を小さめから**。📷 カメラ（15）はアドレスバーで許可する
5. 図の読み方：円 = 状態、二重丸 = 受理状態、左から入る矢印 = 開始状態、矢印のラベル = 読む記号、点線 = ε（文字を読まずに進む）。オレンジ = いまいる状態
6. 文字を入力するスケッチ：01・02・05・08・09・14 は記号のキー（0 1 / a b / かっこ / n + * ( )）がそのまま入力。04 は文字キーがいつも入力で、Tab は正規表現 ⇔ テキストの欄の切りかえ。07・13 は **Tab で編集モード**に切りかえてから入力（編集中は文字キーがすべて入力になり、ほかの操作キーは効かない）

## 困ったときは

| 症状 | 解決法 |
|---|---|
| `drawMachine is not defined` / `dfaAccepts is not defined` | 一番下の「オートマトンの道具」までコピーできていない → 全部コピーし直す |
| キーを押しても反応しない | キャンバスを1回クリックしてからキーを押す。07・13 は Tab で編集モード ⇔ 見るモードを切りかえる（04 は Tab で入力する欄を切りかえる） |
| 文字を打つと勝手に操作される／操作キーが効かない | 07・13 の編集モードと 04 では文字キーはすべて入力になる。07・13 は Tab（13 は Enter でも）で見るモードに戻る。04 のお手本は ↑↓ |
| 矢印が引けない（01・14） | 状態の円の上から押して、別の円の上で離す。離したらすぐに記号のキー（0 / 1 や a / b）を押す。自己ループは円の外に出てから同じ円に戻る。最初の 1 回のクリックは「キーを届かせる（14 は音を ON）」だけで、状態は増えない |
| 画面右下の「自己テスト」が ✗ になる | 道具や機械の表（遷移・文法・状態表）を書きかえた。コンソールでどの項目かを見る。コピーし直せば元どおり |
| 04 の正規表現が赤い「まちがい」になる | かっこの数が合っていない、* や + が 2 つ続いている、など。直すまでは前の機械のまま動く |
| 音が出ない・カメラが動かない | キャンバスを1回クリック ／ アドレスバーの鍵マークで許可（15 はカメラがなくてもマウスで動く。C で切りかえ） |
| 音が大きすぎる | すぐに端末の音量を下げる。全体の音量は 0.2 以下（`MASTER`）。上げないこと |

アルゴリズムはすべてゼロから実装しています：DFA と NFA のシミュレーション（ε 閉包）、たどれる集合だけを作る部分集合構成、ムーアの分割の精密化による最小化、積の構成（∩ ∪ − △）と行き止まりを埋めてからの補集合、幅優先探索による空言語・同値の判定（反例つき）、再帰下降の正規表現パーサとトンプソン構成、ポンピング補題の相手の全探索、最長一致の字句解析、スタックつきの PDA（回文は推測の枝の探索）、チョムスキー標準形の CYK（構文木の数え上げ）、チューリング機械と時空図、2 状態の機械 20736 個の分類（同じ様子のくり返し・ずれながらのくり返しの検出）、階層的な状態機械、トライと失敗リンクのエイホ-コラシック法。各スケッチは起動時に自己テストで、自動販売機のお金の保存（長さ 6 までの全部の入力列）、3 の倍数の DFA = n % 3（n = 0〜1000）、NFA = 部分集合構成の DFA（長さ 10 まで全部）と「最後から 3 文字目」の 8 状態、最小 DFA の状態数 = 総当たりで区別できる状態の数、トンプソンの NFA = JavaScript の RegExp、積の構成の受理 = 2 つの答えの組み合わせ、正規言語では相手が必ず勝てること、字句解析 = 正規表現で一番長いものを選ぶ方法、かっこの PDA = カウンタの判定、CYK = 書きかえの総当たり（長さ 7 までの全部 97655 個）、2 進数の 1 足し = n + 1（n ≤ 255）、忙しいビーバーの (4 個, 6 手)・(6 個, 14 手)・(5 個, 21 手)・(13 個, 107 手)、エイホ-コラシック = 素朴な照合、身ぶりの DFA = 正規表現、などを照合しています。3 状態の忙しいビーバーは、1 の数の最大（6 個）と手数の最大（21 手）が別の機械なので両方を載せています。1 つの単語だけの文字列照合のオートマトン（KMP 型）はシリーズ 17 の 02、セル・オートマトン（ライフゲームなど）はシリーズ 3、書きかえで図形を作る L システムはシリーズ 2 の 03、論理回路はシリーズ 56 の 06 で扱っています。
